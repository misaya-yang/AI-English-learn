# Phase 02 - Anki Import Export Experience

> For agentic workers: enter plan-first mode before editing. Execute this phase only, write the required evidence, and do not advance to the next phase until acceptance gates pass or blockers are documented.

**Goal:** Productize CSV/APKG import and Anki-compatible export so learners can trust VocabDaily as a portable wordbook system.

**Architecture:** This phase improves the import/export workflow around the existing parser, mapping, local persistence, and functional checks. It should not download public decks or change scheduling semantics without a tested mapping decision.

**Tech Stack:** React dialogs, TypeScript import services, `sql.js`, `fflate`, local storage wordbooks, FSRS progress mapping, Vitest, Playwright functional checks.

## Task Spec

Make importing feel like bringing a study asset into the product, not uploading a raw file. The learner should understand what will be imported before commit, what could not be mapped, what progress was preserved, and what to study next.

## Problem Boundary

In scope:

- CSV import UX.
- APKG import UX.
- Field and progress mapping.
- Export UX and file formats.
- Parser safety tests and functional file-upload checks.

Out of scope:

- Public deck marketplace.
- Automatic download from AnkiWeb.
- Real-time Anki sync.
- Paid deck distribution.

## Context Policy

Start from the existing parser and dialogs. Do not replace `sql.js` or `fflate` without a report explaining why the current parser cannot satisfy the acceptance gates.

## Requirements

### R1 Import Preview

Before writing imported data, show deck/file summary, field mapping, sample rows, duplicates, skipped rows, and import destination.

### R2 Mapping Control

The learner can confirm or adjust critical field mappings when auto-detection is uncertain.

### R3 Progress Preservation

APKG progress mapping is transparent. Coarse mode maps review count, status, ease, and next review estimate without implying perfect Anki schedule parity.

### R4 Export Portability

The learner can export current filtered words as CSV, CSV with progress, and Anki-compatible TXT with clear descriptions.

## Test and Regression Requirements

- Add parser tests for representative field names, HTML stripping, duplicate rows, invalid rows, APKG deck summaries, and progress mapping.
- Run functional import checks with synthetic files when credentials and preview server are available.
- Capture desktop and mobile import/export screenshots.

## Compliance and Safety Requirements

- Imported content must be sanitized.
- Source and license fields must survive the flow.
- Do not commit user decks or third-party deck data.
- Do not make remote sync or production migration changes without approval.

## Rollback and Recovery

Rollback by reverting touched files. If new persisted metadata is introduced, include a cleanup function or migration rollback after approval.

## Execution Capture

Use `docs/vocabdaily-learning-ecosystem-prd/reports/phase-report-template.md` and save the phase report at `docs/vocabdaily-learning-ecosystem-prd/reports/vle-02-anki-import-export-experience-report.md`.

## Evaluator Protocol

Evaluate with two files: a synthetic CSV with one invalid row and one duplicate, and a synthetic APKG with two decks and different review counts. The learner should be able to predict the import result before committing.

## Acceptance Criteria

- Import is previewable, explainable, and reversible at the UI level before commit.
- Export makes VocabDaily feel portable, not locked-in.
- VLE-03 can use imported words as trustworthy daily and practice inputs.

## Risks

- APKG field diversity can exceed the current auto-detection rules.
- Imported HTML can create display and security issues.
- Learners may expect exact Anki schedule parity when only coarse progress mapping is supported.
